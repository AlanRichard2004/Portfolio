Case files: how each one works

The covers above are the summaries. These are the full stories: how each project works, why I built it and what it shows.

Onion Routing Simulator

  1. Message
  2. Wrap in layers
  3. Node A peels
  4. Node B peels
  5. Final node delivers

What it is

A Python network simulator that copies the core idea behind Tor. A message is wrapped in one layer of encryption per node on its path. Each node can unwrap only its own layer, so it learns where to send the packet next but never sees the whole route.

Why I built it

I wanted to understand traffic obfuscation and encrypted communication by building it, not only reading about it.

How it is built

Sockets carry traffic between simulated nodes, cryptography provides the layering, and every node runs in its own Docker container on WSL Ubuntu. Isolation confirmed that nodes only talk over the network and made cross-node problems easier to trace.

Skills it shows

  • Socket programming
  • Applied cryptography
  • Container isolation
  • Debugging across nodes

Log Hunter

  1. Read logs
  2. Parse each line
  3. Match regex patterns
  4. Flag anomalies
  5. Write report

What it is

A defensive Python tool that reads Apache, Nginx and syslog files and looks for the traces attackers leave: repeated failed logins (brute force), SQL injection payloads inside requests, and directory traversal paths that try to climb out of the web root.

Why I built it

Analysts face more log lines than anyone can read. I built a first pass that surfaces what deserves attention and explains it in plain language, to speed up early incident response.

How it is built

Custom regular expressions describe each attack pattern. Matches are collected and written as human-readable reports that can be handed straight to a reviewer. You can try the idea yourself in the lab below.

Skills it shows

  • Regex design
  • Log analysis
  • Threat hunting basics
  • Report writing

Bare Metal OS

  1. Boot code (Assembly)
  2. Compile with GCC and Make
  3. Add BusyBox userland
  4. Package bootable ISO
  5. Test in QEMU or USB

What it is

A minimal bootable Linux-based system assembled from scratch, to understand what happens between pressing the power button and reaching a shell.

Why I built it

Security starts below the operating system. Building the boot path myself showed me where kernel components and bootloaders can be attacked or hardened.

How it is built

x86 Assembly and C compiled with GCC and Make, BusyBox for the minimal userland, QEMU for quick virtual tests, and Ventoy for booting the ISO from a USB drive.

Skills it shows

  • Low-level programming
  • Boot process
  • Toolchains and builds
  • OS-level security thinking

How I think about security

Confidentiality

Only the right people should see the data. In my onion routing simulator each node can read only its own layer, so no single node sees the whole route.

Integrity

Data should arrive unaltered and be trustworthy. Protecting integrity at every hop was a design goal of the simulator, and keeping secrets out of source control protects the integrity of deployments.

Availability

Systems must be there when needed. In hospital networks a dropped connection can delay care, so I documented devices and fixed connectivity bottlenecks to keep downtime low.

Defense in depth

No single control is enough. Firewalls (UFW), brute-force blocking (Fail2Ban), VLAN segmentation and log monitoring work together so one failure does not expose everything.

    Field guide
    
  
    Plain-language notes on terms used across this portfolio.
    
  
    SIEM
    A system that gathers logs from many sources into one place so searches and alerts happen in one view. Splunk and the ELK Stack are examples.
    Brute force
    Guessing passwords by trying many combinations quickly. Fail2Ban counters it by banning addresses after repeated failures.
    SQL injection
    Sneaking database commands into an input field so the application runs them. Input validation and parameterized queries prevent it.
    Directory traversal
    Using ../ sequences to climb out of a web folder and read files that should stay private.
    VLAN
    A virtual network segment on shared hardware that keeps groups of devices apart.
    ACL
    A rule list on a router or firewall that allows or blocks traffic by address, port or protocol.
    NAT and PAT
    Translating private addresses to a public one so many devices can share a single internet address.
    IPsec
    A suite of protocols that encrypts and authenticates IP traffic, commonly used to build VPN tunnels.
    IoMT
    Internet of Medical Things: connected devices such as monitors and pumps that need very high uptime.
